# Luna 제품 검증 기준선 선정 — 모델 비교 종료

2026-09-07 기준. 상태: **모델 비교 종료 / Luna 제품 검증 진행 / 운영 배포 미완료**.

## 결정

제품 브리핑 검증의 기준 모델을 gpt-5.6-luna, reasoning low로 고정한다. 모델 선정 논의를 반복하기보다 현재 모델의 실패와 제품 연결 문제를 기록하고 해결한다. 이는 GPT-5 mini보다 사실 정확도가 높다는 결론이 아니다.

같은 8개 입력의 기존 비교에서 GPT-5 mini와 Luna는 제한된 자동 검사 모두 8/8, 4o mini는 최종 계약 포함 3/8이었다. 원문 검토에서 4o mini의 기준 이후 승인·다른 설비 승인 오인이 확인되었다. Luna는 한국어 브리핑 표현에서 우선 후보였지만 품질 보류를 확정 가능으로 표현한 모순이 있었다. 이 한계를 포함해 조건부로 선정한다. 이전 비교 보고서와 원문을 변경하거나 실패를 삭제하지 않는다.

## 이번 보완

- 품질 보류 시 모델의 현재 판단 입력에서 생산 영향, 정지 시간, 손실 수량을 null로 전달한다. 보류 상태에서 영향·손실을 확정할 수 있다고 쓰는 표현을 제한적으로 검사한다.
- 기준 시각·설비·이벤트와 맞는 최신 기록만 현재 이력으로 전달한다. 제외 기록은 식별자·출처·제외 사유만 별도 참조 메타데이터로 남기고 승인 상태나 시각은 현재 본문 입력에서 제외한다. 원본 패킷은 보존한다.
- 승인 기록이 있는데 “승인 여부 재확인이 아니라 준비·일정 검토”라고 쓴 정상 문장을 오판하던 채점기를 수정했다. 실제 승인 대기·승인 검토로 되돌리는 표현은 계속 거절한다.
- 실제 화면의 역할 탭을 바꾸어도 로그인 역할의 브리핑이 남던 문제를 수정했다. 표시 역할만 탭을 따르고 생성·실행 권한은 계정 기준을 유지한다.
- 프롬프트 버전은 agent-review-summary-prompt-v2.6-current-state-hold. 실험 공통 한국어·작성순서 지침과 모델 선택은 검증 실행기에 고정되어 있으며, 운영 설정·배포까지 반영했다는 뜻은 아니다.

## Luna 8건 재검증

동결된 기존 8개 패킷에 보완한 입력 조립과 프롬프트를 적용했다. 8회 최초 생성 및 3번 재작성 1회, 총 9회 생성했다. 원문·전송 이벤트·사용량·원래 판정을 모두 보존했다.

| 판정 시점 | 결과 | 해석 |
|---|---|---|
| 실제 API 실행 당시 최종 판정 | 7/8 | 승인 사례 1건이 채점기의 부정문 오탐으로 거부됨 |
| 채점기 수정 후 최초 원문 오프라인 재검증 | 8/8 | 추가 API 생성 없이 같은 원문을 재검증 |
| 백엔드 회귀 검사 | 328 통과 | 계약·입력 경계·내용 검사 포함 |
| 프런트엔드 관련 검사 | 15 통과 | 역할 표시와 계정 권한 유지 포함 |
| 변경 파일 공백 검사 | 통과 | git diff --check |

미래 승인과 다른 설비·이벤트 승인은 현재 승인 미확인으로, 부품 근거가 없는 사례는 준비 미확인으로 설명했다. 품질 보류 사례는 영향·손실 미확정을 유지했다. 이것은 이번 원문에 대한 관찰이며 일반 정확도 100%가 아니다. 표현 일부에 “점검 승인”과 “작업요청 승인”이 혼용되고 설명이 길어지는 문제는 사용자 원문 평가 대상으로 남긴다.

## 화면 검증 범위

실제 factory-status-original 화면 템플릿, 런타임, 표시 모듈을 복사한 로컬 재생 페이지에서 저장된 응답을 입력했다. 보전에서 생산관리자 탭으로 전환했을 때 생산관리자 원문 표시, 보전 원문 미잔존, 생성 버튼 비활성, 가로 넘침 없음(1280px)을 확인했다. 화면 캡처: ui-manager.png.

인증·실제 DB 조회·요약 저장·출처 클릭의 종단 연결은 이번 재생 검증에 포함되지 않았다. 재생 페이지의 미산정 KPI는 운영 데이터 연결을 생략한 결과다. 생산 영향과 실행 버튼의 실제 운영 연동을 입증하는 화면으로 발표하지 않는다.

## 남은 제품 검증

1. 검증 실행기의 한국어 지침·모델 설정과 실제 서비스 생성 경로를 일치시키고, 동일 패킷에서 실제 저장 및 GET 재조회 확인.
2. 실제 DB 읽기 경로에서 현재 대상·기준 시각·캐시 버전 일치와 거절 시 fallback 표시 확인.
3. 화면에서 문장별 근거를 추적할 수 있는 출처 연결, 역할별 다음 결정의 실무 명확성 검토.
4. 사용자 원문 평가. 3개 설비 중심의 8개 상태 변형은 독립 현장 8건이나 풍부한 관계 확장 시험이 아니다.

관계 확장 성능, 현장 효용, 업무 시간 절감, 비용 우위는 not_measured로 남긴다. json_schema 요청 거부 후 json_object로 재요청된 전송 이벤트가 있으므로 공급자 강제 스키마 보장을 주장하지 않는다. 검사기는 제한된 규칙이며 모든 의미 모순을 검증하지 않는다.

중대한 사실 오류가 반복되거나 서비스 요구·지연·비용 조건이 바뀔 때만 모델 비교를 재개한다. 이번 변경은 실제 DB 상태, Closed-loop 승인/실행, 운영 모델 배포를 변경하지 않는다.

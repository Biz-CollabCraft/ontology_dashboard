# 설명 경계 개선

## 원인

Luna 120회 실호출의 최종 탈락 6건을 원문과 검증 코드로 대조했다. 5건은 현행 문체/지시 경계에 걸렸고, GS-007 4회차는 자료 보강 후 재판단을 위한 목적절을 현재 생산 영향 확정 주장으로 오인했다. 자동 검사 판정은 현장 유용성이나 임의 산문의 의미 검증 전체를 보증하지 않는다.

프롬프트에는 다음 행동으로 마무리하라는 요구와 지시형 판단 문장을 금지하는 검증이 충돌했다. 또한 역할별 quote에 적용하던 내부 용어·단위 검사가 title/summary에는 적용되지 않았고, 생산 영향 보류 검사에서도 title이 빠졌다.

## 수정

- 첫 생성 입력의 expression_policy에 확인된 기록·조건부 추정·미확인 정보·사람의 다음 판단 조건을 구분했다. 정책은 표현 규칙이며 새로운 운영 사실을 제공하지 않는다. 두 프롬프트 builder가 같은 규칙을 사용하고 원본 packet을 변경하지 않는다.
- 마지막 문장은 행동 지시 대신 입력에 있는 미확인 조건과 그 조건이 막는 판단의 관계를 설명하도록 프롬프트를 정리했다. 승인 기록이 있을 때만 현재 승인 상태를 보고하게 명시했다. 단위·내부 용어의 한국어 표기 규칙도 첫 요청 입력에 명시했다.
- 제목·공통 요약·역할별 quote에 동일한 검사 범위를 적용했다. 실제 현재 확정 주장과 별도 문장의 확정 주장은 계속 거절한다. `할 수 있도록` 목적 표현을 `할 수 있습니다` 현재 가능 주장으로 오인하지 않도록 좁게 수정했다.
- 정지 N분 가정 같은 필요한 추정 조건은 내부 표현으로 제거하지 않는다고 재작성 피드백을 명확히 했다.
- 프롬프트 버전을 v3.5-expression-boundaries로 올렸다. 기존 v3.4 저장본을 새 정책의 exact 저장본으로 재사용하지 않는다. 권한·실행·사실·source refs·최대 1회 재작성 및 fallback 경계는 유지했다.

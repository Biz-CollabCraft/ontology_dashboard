# 생성·조회 분리의 시간·토큰 측정

2026-09-09 측정. 판정: **로컬 저장본 조회 시간은 실측**, **토큰 절감 및 모델 대기를 포함한 시간은 과거 실호출 기록 기반 재생**이다. 신규 외부 호출·신규 토큰은 모두 0이다. 운영 실측 A/B나 PR #173의 독립적인 개선 효과가 아니다.

## 비교 대상과 조건

- 분리 전 기준: commit `5126b4290eafc5e3855bc0c71618dae02d47aa40`의 `systems/backend/app/mvp/service.py`에서 `agent_review_summary` 메서드를 AST로 추출해 그대로 실행. 당시 router GET이 이 메서드를 호출하고 메서드가 매번 `provider.generate`하는 것을 확인했다.
- 분리 후: commit `293f5ba5`의 실제 materialization + SQLite repository + `cached_agent_review_summary_for_packet` 경로. 최초 1회 명시 생성 후 14회 저장본 조회.
- 이전 checkout 전체를 실행한 비교가 아니다. 입력 패킷, 계약 검증 함수, 공급자 응답을 동일하게 맞춰 조회 시 생성 여부의 효과를 분리했다. 입력 패킷 구성, HTTP API/인증, 브라우저 렌더링은 제외한다.
- 원본은 기존 Luna v3.4 실호출 8 fixture × 15회=120개 생성 기록, HTTP 181회다. 이 120개 각각을 하나의 독립된 고정 근거 구간으로 사용하고, 구간마다 동일 근거를 15번 조회했다. 각 비교군 1,800회 메서드 실행이며 **1,800회 새 모델 생성이 아니다**.
- 구간별로 분리 전은 같은 기록된 생성 결과를 15회 반환하고, 분리 후는 최초 생성 결과를 저장해 재사용한다. 모든 원본을 사용하여 특정 성공 회차만 고르지 않았다. 114개 ready와 6개 fallback 구간을 유지한다.
- 기록된 응답을 반환하는 공급자 대역은 네트워크 요청을 수행하지 않는다. 모델 품질·변동성과 새로운 프롬프트 효과를 측정하는 실험이 아니다.

## 결과

| 지표 | 분리 전 | 분리 후 | 근거 |
|---|---:|---:|---|

p95는 nearest-rank 방식이다. 기존 Luna 보고서의 25.54초는 당시 생성·검증·저장·재조회 전체 시간이므로 이번 HTTP 시간+로컬 실행 재생 값과 혼용하지 않는다. 요청 시간 합계는 분리 전 47,827.0초→분리 후 3,208.3초(약 93.29% 감소)이나, **동시 실행의 벽시계 완료 시간이 아니라 요청별 소요시간의 합계**다.

첫 생성은 약 25초가 그대로 필요하고 저장·검증 오버헤드가 추가된다. 조회 15회 중 최초 생성이 1회이므로 느린 요청이 6.67% 남아 전체 p95는 수초 단위다. 생성 전 GET이 빨리 `pending`을 반환하는 것은 AI 설명을 빨리 완성했다는 뜻이 아173니다.

## 검증 및 의미

- 120개 구간 모두 저장본이 해당 생성 결과와 동일했다. 저장본 조회 1,680회 추가 생성 함수 호출 0.
- 120개 구간 모두 근거 해시 변경 시 기존 설명을 반환하지 않았다. miss 조회도 생성 함수 호출 0.
- 모든 전달 결과는 현행 계약 검증을 통과했다. fallback 6개 구간은 AI 성공으로 합산하지 않았다.
- 원본 packet hash가 실호출 manifest와 일치함을 실행 중 검증했고, 사용한 코드·기록 해시를 별도 manifest에 남겼다.
- 집계 원시 행 120개, 생성 함수 호출 1,800→120, 토큰 총합 1,932,180 및 배수 계산을 별도로 재검산했다.

## 해석 범위

이 수치는 동일 근거가 바뀌지 않는 동안 15회 조회하는 조건의 결과다. 동일 근거 조회가 1회면 토큰 감소 0%, 2회면 50%, 5회면 80%, 15회면 93.33%다. 실제 절감률은 조회 빈도, 근거 변경 빈도, 강제 재생성, 실패 재시도에 따라 달라진다. always watcher의 fallback 재시도·사전 생성 후 아무도 조회하지 않는 경우·다중 worker 경쟁은 이번 조건에 넣지 않았다.

현재 demo도 이미 생성·조회가 분리되어 있다. 따라서 이 결과는 역사적인 분리 전 구조와 현재 구조 사이의 효과이며, 최근 PR #172/#173이 각각 이만큼 추가 개선했다는 뜻이 아니다. 운영 비용 청구액, 운영 PostgreSQL/브라우저 응답시간, 사람의 판단 시간, 새 프롬프트 성능은 미측정이다.

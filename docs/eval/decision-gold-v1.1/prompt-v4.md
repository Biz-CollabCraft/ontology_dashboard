# 의미 해석 프롬프트 v4

에이전트 검수에서 합의한 일반 기준을 런타임 text interpreter에 반영했다. 사례 ID, 원문 예문, 정답 라벨 목록은 프롬프트에 넣지 않았다. 프롬프트 변경을 구분하도록 interpreter 이름을 quoted-text-evidence-interpreter-v4로 갱신했다.

- 정보 누락은 기록/값의 부재·미확인을 원문이 명시한 경우에만 붙인다. 측정 요청, 기록 검토 요청, 의견 충돌, 불명확한 지시어에서 누락을 추론하지 않는다. false는 자료 완전성 보증이 아니다.
- 선택 가능한 측정은 비필수라고 해도 optional이다. 명시적으로 철회·불필요·기록 검토로 대체된 측정은 not_required다. 교육/연구 목적이어도 필수라고 명시하면 required다.
- 작업 종류를 모르면 측정 요청 여부도 unclear일 수 있다. 하지만 가능한 해석이 모두 명확한 비측정 작업이면 meaning의 모호함을 유지하면서 measurement_status는 not_stated로 둔다.
- 조건값이 없는데 조건이 성립했다고 추론하거나 조건부 요구를 곧바로 선택 사항으로 바꾸지 않는다. 조건부 측정의 별도 출력 상태는 추가하지 않았으므로 이 범주의 한계가 해소된 것은 아니다.

JSON schema, 서버 파생 규칙, Policy Guard, read-only tool, Human-in-the-loop 경계는 유지했다. 독립적인 모호 지시와 필수 측정 요구가 한 원문에 공존하는 조합은 기존 단일 meaning/status의 표현 한계가 남아 있으며 이번 프롬프트만으로 해결됐다고 보지 않는다. 미정 4건과 데이터 라벨은 바꾸지 않았다.

기존 v3 모델 비교 결과와 입력 해시는 보존한다. 후속 [v4 회귀 평가](prompt-v4-evaluation-2026-09-14.md)에서 정보 누락 일치 개선과 의미 분류/일부 보류 회귀를 함께 관찰했다. 오프라인 테스트는 계약·출처 검증·정책 경계 회귀 확인이며 자연어 이해 정확도 증거가 아니다.

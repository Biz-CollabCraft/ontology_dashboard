# 근거 Selection 개수 한도 비교 — 2026-09-09

## 결론

기존 합성 사례에서 공정관리자에게 지정된 필수 출처 5개를 모두 보존하는 최소 한도는 8개였다. 이는 해당 사례와 평가표에서의 최소값이며, 일반적인 최적값을 증명하지 않는다. 데이터 만료와 복수 제약에서는 더 큰 한도가 필요했다. 또한 필수 후보를 출처별로 대표화하는 과정에서 다른 의미의 제약 항목이 누락되는 현상을 확인했다.

## 실행 범위

- 기존 운영 맥락 합성 fixture와 실제 후보 생성·관계 해석·선별 함수를 사용했다.
- 기본, 생산 데이터 만료, 생산 데이터 만료 및 동일 출처의 복수 제약: 3가지 조건.
- 공정관리자·현장작업자·시스템관리자: 3가지 역할.
- 각 조건의 1개부터 전체 후보 수까지 모든 정수 한도와 무제한을 비교했다.
- 총 237개 조합. 각 조합을 동일 입력으로 재실행하여 결정성을 assert했다. 독립적인 실제 업무 사례 237개를 의미하지 않는다.
- 기존 필수 출처 5개 평가표를 유지했다. 다른 역할 비교는 민감도 확인이며 역할별 정답 평가가 아니다.
- 만료된 생산 데이터의 필수 출처 2개는 unavailable로 별도 기록했다. 해당 조건의 출처 보존율 분모는 남은 3개다. 원래 5개가 모두 보존되었다는 의미가 아니다.
- 모든 limitation 후보 ID를 검사하고, 별도로 required_for_boundary 후보 ID 전체의 누락도 검사했다. 후보 ID 보존은 엄격한 구조 검사이며 의미적 동등성이나 최종 LLM 출력의 안전성을 직접 평가하지 않는다.

## 발견: 같은 출처의 사실과 관계 제약이 대표화 과정에서 분리됨

기본 사례의 한도 8개에서 다음 후보가 누락됐다.

`relationship:inventory_snapshot_reports_part:MAINT-READINESS-SNAPSHOT-2026-09-02-01->PART-002`

이 후보는 required_for_boundary=true, limitation_state=not_connected이다. 동일 source_ref의 inventory_snapshots 사실 후보는 선택되지만 limitation_state=null이며 value_summary에는 part_id만 남는다. 따라서 출처 ID 보존만으로 이 관계 제약 항목의 보존을 증명할 수 없다. 이 실험은 selected 후보의 누락을 검증하며, 다른 입력 필드로 전달되는 전체 후속 파이프라인에서 제약이 사라진다고 단정하지 않는다.

원인은 `_deterministic_subset()`이 필수 후보를 `_dedupe_by_source_ref()`로 먼저 대표화하고, 대표가 되지 않은 필수 후보는 일반 순위 경쟁으로 돌리는 구조다. 모든 필수 후보 ID까지 보존하려면 이 기본 사례의 공정관리자에서는 25개가 필요했다. 이는 25개를 새 기본값으로 권고하는 결과가 아니다. 출처가 같은 서로 다른 의미의 제약을 보존하는 정책을 먼저 검토해야 한다.

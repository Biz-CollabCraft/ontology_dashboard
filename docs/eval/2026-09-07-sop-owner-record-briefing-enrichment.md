# SOP·점검 결과·작업 상태 브리핑 입력 보강

SOP와 기존 점검·작업 기록을 읽어 브리핑에 설명하는 경로를 보강했습니다. Closed-loop 생성·승인·실행 명령은 변경하지 않았습니다.

## 변경 내용

- SOP: 식별자·버전·제목, 점검 항목, 판정 범위, 임계값·비교 연산자·단위·조건별 결과, 현장 확인 필요 여부를 모델 입력에 보존합니다.
- 관측 근거: 모델 요인의 실제 값·단위와 예측 기간을 전달합니다. 임계값을 비교할 관측값/조건이 없으면 추정하지 않도록 안내합니다.
- 점검 결과: 발견 사항·측정값·체크리스트·기록된 outcome과 관련 작업요청 식별자를 중간 변환 단계에서도 보존합니다.
- 작업 상태: 기록된 상태와 원본 작성·갱신·승인·시작·완료 시각을 보존합니다. 배정된 담당자를 승인자로 추정하지 않습니다.
- 시점/대상: 기준 이후 기록, 시각 미확인, 다른 설비 및 다른 이벤트 기록을 구분해 모델에 전달합니다. 이 분류는 LLM 주장 전체를 자동 검증하는 의미 평가기는 아닙니다.
- 데이터 품질 보류: 기존 점검·작업 기록이 있으면 읽습니다. 위험 요인과 SOP를 임의로 복원하지 않습니다.
- 표현: 실제 기록에 근거한 승인·완료 상태 설명을 허용합니다. 공통 요약 1~2문장, 역할별 상세 3~5문장으로 근거·준비 조건·다음 판단을 설명하도록 변경했습니다. 입력에 없는 재고 수량·담당자·확정 납기를 만들지 않습니다.
- 캐시: 프롬프트 버전을 v2.2로 갱신했습니다. SOP 조건과 점검 기록이 바뀌면 기존 캐시 키와 구분됩니다.

## 계약 영향

읽기 전용 agent-review-packet 스키마에 선택 필드를 추가했습니다. 기존 입력은 유효하며, 새 필드가 포함된 패킷을 엄격하게 검사하는 소비자는 갱신된 스키마가 필요합니다. 공식 점검 결과·작업요청 생성·승인 명령, 권한 규칙과 DB 마이그레이션은 변경하지 않았습니다. 승인/완료를 설명하는 표현을 허용하기 위해 기존 금지 표현 검사를 전면 해제하지 않았습니다.

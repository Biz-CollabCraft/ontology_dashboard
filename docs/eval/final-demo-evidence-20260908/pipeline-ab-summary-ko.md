# AI 브리핑 파이프라인 기여도 — 120회 비교

기존 파이프라인 포함 A 120회를 재사용하고 direct B 120회를 신규 실행했다. 동일한 8개 로컬 fixture 패킷을 15회씩 사용했으며, B는 4개 병렬로 실행했다. 모델은 gpt-5.6-luna다.

| 지표 | A: 파이프라인 포함 | B: direct |
|---|---:|---:|
| 유효 JSON / 평가 회차 | 120/120 | 120/120 |
| 공통 내용 검사 통과 후보 반환 | 97/120 (80.8%) | 25/120 (20.8%) |
| 내용 검사 경고가 있는 후보 반환 | 0/120 | 95/120 |
| 원문 편집 스키마 통과 | 0/120 | 120/120 |
| 원문 전체 검사 통과 | 0/120 | 14/120 |
| 반환 본문의 내용·표현 검사 모두 통과 | 15/120 | 14/120 |
| 성공한 모델 생성 수(재작성 포함) | 220 | 120 |
| 회차 지연 중앙값 | 22.8초 | 10.2초 |

**공통 내용 검사 통과 후보의 반환 비율 차이는 +60.0%p다.** A는 23회 후보를 거절했고, 반환한 97개는 좁은 역할별 필수 항목·기록 범위·계약 검사를 통과했다. B는 이 검토·거절 계층 없이 원문을 반환했다. 자동 검사 경고에는 부정문 오탐이 있으므로 95회를 모두 환각이나 위험한 답변으로 부를 수 없다.

전체 품질 성공으로 확대하면 안 된다. A 원문 120개 모두에 편집 스키마가 허용하지 않은 역할별 추가 필드가 있었으며 제품 merge가 이를 제거했다. 반환 본문 97개 중 82개에는 ISO 날짜 표현이 남았다. 따라서 엄격 원문 전체 성공은 A가 개선하지 못했고, 날짜까지 포함한 본문 품질 통과도 15회 대 14회다.

기존 A의 94/120(78.3%)은 별도 평가기 수치다. 97회와 다른 이유는 기존 추가 운영 주장 정규식이 부정·불확실성 문장 3개까지 실패로 표시했기 때문이다. 원래 수치를 덮어쓰지 않고 공통 재채점 결과와 함께 보존했다.

발표용으로 쓸 수 있는 문장:

> 동일한 8개 fixture를 15회씩 비교했을 때, 파이프라인은 역할별 필수 항목과 기록 범위를 검사하고 후보를 재작성·거절하여 공통 내용 검사를 통과한 후보의 반환 비율을 20.8%에서 80.8%로 높였습니다. 다만 원문 스키마와 날짜 표현 문제는 남았으며, 이는 현장 효과나 인간 유용성 검증이 아닙니다.

A는 과거 결과를 재사용한 비동시 비교이며 최초 원문·전체 소스 해시·실제 fallback/UI 전달은 과거 자료에 보관되지 않았다. 따라서 재작성 단독 기여나 실제 화면 누출 감소는 측정하지 못했다. API 연결 오류는 양쪽 모두 0회였고, JSON schema 요청의 HTTP 400 후 JSON 모드 성공은 별도 형식 협상으로 계산했다.

입력은 로컬 fixture이며 API만 실제 호출했다. DB 접근·쓰기, 운영 상태 변경과 배포는 없었다. 비용과 인간 유용성은 not_measured다. 초기 형식 안내가 빠진 direct 프로토콜의 저장 응답 20개는 별도 보존하고 주 비교에서 제외했다. 중단 시 진행 중 호출의 사용량은 알 수 없다.

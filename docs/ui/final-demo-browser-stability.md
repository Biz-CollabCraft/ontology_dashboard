# 실제 화면 안정성 추가 검증 — 2026-09-08

최신 통합 상태: [최종 통합 보고](final-demo-ai-briefing-integration.md).

작업 브랜치: `codex/demo-ai-briefing-placement`.

기존 40/40은 입력→화면 제공의 코드 계약 검사다. 실제 브라우저의 네트워크 오류, 요청 경쟁, 재시도 안정성과 구분한다. 기존 24개 정상 화면 조합에 추가로 실제 Chromium에서 응답 지연·차단·손상을 주입했다. 실제 로컬 서버 응답을 가져온 뒤 필요한 실패 조건만 변경했으며, 이 결과는 live DB나 배포 환경의 신뢰도 측정이 아니다.

## 발견한 문제와 수정

첫 검사 10개 중 5개 실패, 5개 통과. 실패 원인은 세 종류였다.

- 같은 이벤트 루프에서 버튼을 20회 실행하면 요청 20개가 발생했다. React 상태 갱신에 앞서 적용되는 요청 잠금을 추가해 1개만 허용한다.
- 다른 설비 응답, pending 응답, 본문 없는 응답에서도 상단이 성공으로 바뀌고 읽음 확인이 가능했다. 입력 해시/사례 외에도 설비, 모드, 저장 상태, 본문 구조를 함께 확인한 뒤 성공을 표시한다.
- 불완전한 입력 응답이 React 렌더링 오류로 이어졌다. 화면에서 사용하는 입력 구조와 전달 계약을 먼저 확인하여 오류 안내를 유지한다.

추가로 요청에 10초 제한을 적용했다. 무응답 후 버튼 잠금이 해제되고 재검사가 가능하다. 사례 전환 시 기존 요청 취소와 읽음 확인 해제는 유지한다.

수정 파일: `systems/frontend/src/features/operations/overview/FinalBriefingDemo.tsx`.

## 최종 결과

실제 브라우저 안정성 **16/16 통과**, 페이지 실행 오류 0.

1. 20회 연속 클릭 → 서버 요청 1회
2. 늦은 검증 응답 중 사례 전환 → 이전 문장 표시 차단
3. 검증 연결 실패 → 이전 문장 제거, 재시도 성공
4. 서버 503 → 오류 표시, 재시도 성공
5. 입력 해시 불일치 → 성공/읽음 확인 차단
6. 설비 불일치 → 성공/읽음 확인 차단
7. pending 응답 → 성공/읽음 확인 차단
8. 본문 없는 응답 → 성공/읽음 확인 차단
9. 잘못된 입력 응답 → 화면 유지, 오류 표시
10. 새로고침 → 읽음 상태 초기화
11. 10초 무응답 → 종료 후 재시도 성공
12. 입력 조회 연결 실패 → 복구 후 정상 표시
13. 사례 30회 전환 → 마지막 입력만 표시
14. 1280px 발표 화면 → 가로 넘침 없음
15. 1440px 발표 화면 → 가로 넘침 없음
16. 1920px 발표 화면 → 가로 넘침 없음

프론트 표시 회귀 32개와 TypeScript/Vite 빌드 통과. 실제 서버 정상 경로 **24/24 조합** 재검증 통과. 서버 replay 회귀 **20개** 통과.

정상 경로 재검사 중 품질 보류 사례의 상태 누락도 발견했다. 보관된 입력의 보류 사실을 ViewModel의 `data_status.is_data_quality_hold`로 전달하고, 화면에서는 위험값/등급 미제공을 유지한 채 확인 필요 상태로 표시하도록 수정했다. 테스트 지원 `briefing_demo_replay_support.py`와 화면 연결을 수정하고 전용 회귀 검사를 추가했다.

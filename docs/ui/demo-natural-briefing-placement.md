# demo 자연어 브리핑 화면 연결

최신 통합 상태: [최종 통합 보고](final-demo-ai-briefing-integration.md).

최신 demo `ae6141ef98cb4ee6ec6ea405b798f97b6fd9b1e1`에서 만든 `codex/demo-ai-briefing-placement` 작업이다.

## 반영한 로컬 구현

`codex/pr167-ai-briefing-optimization-plan` 작업 공간의 커밋되지 않은 자연어 브리핑 구현을 포함해 선택적으로 반영했다. 원본 작업 공간은 변경하지 않았다.

- 자연어 프롬프트: `agent-review-summary-prompt-v3.4-next-decision-emphasis`
- 응답 계약: `agent-review-summary-v1.1`, 기존 v1.0 읽기 호환 유지
- 역할: 설비 엔지니어 / 보전 담당자 / 생산 관리자
- 현재 상태 → 원인 관계 → 확인된 기록 → 남은 공백 → 다음 판단의 문장 흐름
- 근거 선별, 소유 도메인 기록 대조, 문장 검증·재작성, 정확히 일치하는 캐시 재사용 정책

## 화면 배치

- 엔지니어: ‘선택 설비 근거 요약’의 상태 문구 다음, 위험 기여 요인 목록 앞
- 보전팀: 선택 요청의 식별·상태 정보 다음, 작업 입력 앞. 입력 폼과 함께 스크롤
- 생산 관리자: 중앙 ‘생산 대응 검토’의 위험 추세 그래프 앞. 중앙 영역만 스크롤하며 오른쪽 승인 검토 유지

공통 `NaturalBriefing` 컴포넌트가 역할별 자연어를 표시한다. 본문은 로컬 `briefFormat`을 사용해 문장 줄·강조·기록 시각·접는 근거를 텍스트로 렌더링한다. 임의 HTML을 실행하지 않는다.

최초 진입은 저장 결과 GET만 수행한다. 생성 권한이 있는 사용자만 명시적으로 POST를 요청할 수 있으며, 생성 후 저장 결과를 다시 조회한다. 설비·이벤트·역할·근거·요청 상태가 변경되면 이전 문장을 즉시 비우고 진행 중인 조회를 취소한다. fallback·stale·다른 설비 응답은 자연어 브리핑으로 표시하지 않는다. 브리핑 실패는 기존 판단 근거나 승인·점검 기능을 막지 않는다.

## 확인 결과

- 프런트엔드 프로덕션 빌드 및 초기 번들 예산 검사 통과
- 브리핑 및 관련 화면 테스트: 47 passed
- 로컬 자연어/스키마/생성 정책/근거 선별 회귀: 227 passed
- 브리핑 운영 API/권한/캐시/이벤트 연결 회귀: 30 passed
- Chromium에서 세 역할 실제 컴포넌트에 로컬 Gold v5 문장 5줄을 표시: JS 오류 없음, 문장 영역 가로 넘침 없음, 화면 열기만으로 생성 POST 없음

브라우저 검토는 고정 입력을 사용하는 UI replay이며 실제 LLM 생성·운영 DB·운영 배포 검증이 아니다. 생산 화면의 기존 참고 경제값과 브리핑의 추정값은 출처·조건을 구분해서 해석해야 한다. 프로젝트 전체 테스트를 통과했다고 주장하지 않는다.

기존 demo 보전 화면 테스트의 예전 목록 이름·자동 선택 기대는 최신 demo 화면과 맞지 않아 수정했다. 구형 API 테스트도 제거된 비교 계정 대신 실제 세션에서 생성 권한만 제외하도록 수정했고, 모의 LLM 응답은 자연어 전용 출력 계약에 맞췄다.

## 화면 캡처 재현

프런트엔드 Vite를 로컬 3318 포트에서 실행한 뒤 저장소 루트에서 `node scripts/capture_natural_briefing.mjs`를 실행한다. `BRIEFING_PREVIEW_URL`과 `BRIEFING_SCREENSHOT_DIR`로 서버 주소와 캡처 저장 위치를 지정할 수 있다. 화면 검토 입력은 테스트 전용 HTML/TSX에만 주입하며 제품 진입 경로는 변경하지 않는다.

마지막 다음 판단 문장은 결정 대상·조건·근거 1~2곳만 굵게 강조한다. 프롬프트 버전을 갱신했으므로 실제 생성 결과는 새 버전으로 생성해야 반영된다.

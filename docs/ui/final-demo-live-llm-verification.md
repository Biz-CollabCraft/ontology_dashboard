# 최신 프롬프트 실제 LLM 확인

2026-09-08 · 사용자 승인 후 고정 데모 패킷 2개를 OpenAI API로 전송했다.

- 대상 코드: `53d646ea`, 프롬프트 `agent-review-summary-prompt-v3.4-next-decision-emphasis`
- 모델: `gpt-5.6-luna`, `reasoning_effort=low`, `max_completion_tokens=4096`, 응답 제한 90초
- 경로: 실제 선택 근거 구성 → 실제 제공자 호출 → 내용 검사 → 피드백 재생성 → 계약 검사
- 입력: 기존 시연 사례 1, 2. DB 쓰기·승인·정비 실행 없음.

| 입력 | 첫 응답 | 재검사 후 | 최종 계약 오류 |
|---|---|---|---|
| 1 | 정비 권고 설명·한국어 단위 문제 | 통과 | 0 |
| 2 | 내부 표현 문제 | 통과 | 0 |

첫 응답 통과는 0/2, 각 1회 피드백 재생성 후 최종 반환은 **2/2**다. 최초 응답부터 정확한 결과를 냈다고 주장하지 않는다.

전송 단계에서는 각 생성 요청의 JSON Schema 모드가 HTTP 400을 반환했고, 기존 호환 제공자의 JSON object 재요청이 HTTP 200으로 성공했다. 따라서 생성 응답 4개를 얻기 위해 HTTP 요청은 8회였다. 원격 strict schema 모드 성공으로 간주하지 않는다. 서버의 내용·계약 검사는 재요청 후에도 적용했다.

제공자가 보고한 합산 토큰은 61,506개이며 실행 구간은 04:19:24~04:20:09 UTC다. 두 사례의 관측일 뿐 서비스 지연 통계나 청구 비용 측정이 아니다.

실제 반환된 2개 응답 × 3역할을 현재 화면 포맷터에 전달하여 문장 3~5개, 상대 날짜, 한국어 단위, 근거 토큰 제거, 마지막 판단 문장의 볼드를 **6/6 확인**했다. 이번 신규 응답 자체를 브라우저에서 재시연하거나 DB에 저장한 검증은 아니다. 기존 전체 연결 브라우저 검사는 통제된 외부 응답을 사용했다.

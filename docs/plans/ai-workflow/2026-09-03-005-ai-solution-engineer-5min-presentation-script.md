## 8쪽. 신뢰성과 처리 비용 비교

### 시간

45초

### 발표 문장

평가는 세 방식으로 나눴습니다. A는 AI가 바로 답하는 방식, B는 정리된 근거를 주는 방식, C는 응답 검사와 장애 처리까지 적용한 방식입니다.

120회라는 숫자는 8개 gold 시나리오를 각각 15번 반복한 것입니다. 공장 전체 통계라기보다, 같은 근거를 여러 번 넣어도 AI 요약이 정해진 형식, 출처 근거, 역할별 표현, 금지 주장 경계를 안정적으로 지키는지 보는 release-gate로 잡았습니다.

C는 잘못된 근거와 위험한 응답을 더 잘 막았습니다. 별도 live LLM 120회 실행에서는 120개 모두 정해진 형식으로 통과했고, fallback은 0건이었습니다. 응답시간은 p50 약 3.9초, p95 약 5.8초였습니다.

토큰은 기존 120회 산출물 기준으로는 provider 청구 원본이 아니라 입력과 출력 크기 기반 추정값입니다. 120회 기준 총 215,835 tokens, 평균 1,798.6 tokens로 기록했습니다. 이후 평가 harness는 provider가 usage를 주면 실측 usage로 저장하도록 보강했고, 1건 smoke에서 provider_reported 기록을 확인했습니다. 최신 72회 workflow 비교에서는 B3가 B1보다 추정 token을 27,918 줄였지만, 일부 invalid row와 fallback/reuse caveat가 있어 비용 확정값으로 말하지는 않습니다.

즉, 정확도 하나가 아니라 신뢰성, 응답 시간, 사용량, 답변 가능 범위를 함께 보되, 측정값과 추정값을 나누어 기록했습니다.

### 질문 유도점

- A/B/C에서 실제 차이가 가장 컸던 지표는?
- 응답 시간이 늘어도 C를 사용할 이유는?
- 안전한 답변 제공률은 어떻게 계산했는가?
- 상황에 따라 B와 C를 나눠 적용할 수 있는가?

# 예상 Q&A 압축 답변

## 왜 근거 묶음을 따로 만들었나요?

AI에 모든 데이터를 그대로 주지 않고, 같은 설비와 시점에 연결되고 출처를 확인할 수 있는 데이터만 전달하기 위해서입니다. 근거와 AI 문장을 분리하면 문장이 달라져도 어떤 사실을 사용했는지 따로 확인할 수 있습니다.

## 시간 정합성은 어떻게 확인했나요?

각 근거에 기준시각과 버전을 남기고, 오래된 데이터나 서로 다른 시점의 데이터를 일부러 넣어 정상 근거에 포함되는지 검사했습니다. 시점이 맞지 않으면 사용하지 않거나 제한된 답변으로 처리했습니다.

## 오탐과 미탐도 평가했나요?

이번 평가는 이상탐지 모델 자체의 오탐과 미탐이 아니라, 탐지 결과를 받은 이후 AI 판단 지원 흐름을 평가한 것입니다. 탐지 모델까지 평가한다면 미탐과 오탐의 현장 비용을 다르게 두고 정밀도와 재현율을 함께 봐야 합니다.

## 왜 LangGraph를 사용하지 않았나요?

현재는 에이전트가 하나이고 분기와 상태 변화가 단순해서 일관된 파이프라인으로 충분했습니다. 간단한 상태 분기 실험도 했지만, 현재 복잡도에서는 얻는 이점보다 구조가 더 복잡해졌습니다. 에이전트나 분기, 오래 실행되는 작업이 늘어나면 다시 검토할 계획입니다.

## 협업은 어떻게 했나요?

구현 전에 PR로 설계 의도와 구현 범위를 먼저 공유했습니다. 팀원이 맡은 영역과 제가 맡은 영역을 합의한 다음 구현해, 같은 기능을 서로 다르게 해석하는 문제를 줄였습니다.

## 평가의 한계는 무엇인가요?

현재 결과는 로컬 구현과 가상 상황, 그리고 고정된 live LLM 평가 산출물 기준입니다. 실제 MES나 정비·재고 시스템 연결, 장기 운영, 비용 절감과 현장 지표 개선은 아직 검증하지 않았습니다. 기존 token은 추정값이고 cost는 가격 설정이 없어 금액으로 확정하지 않았습니다. 보강 후 1건 smoke에서는 provider usage가 반환되어 `provider_reported`로 기록되는 것을 확인했습니다.

| p50·p95 | 보통 걸린 시간과 느린 경우의 시간 |

# 최종 리허설 기준

- 화면의 문장을 전부 읽지 않는다.
- 한 문장을 길게 이어 말하지 않는다.
- 슬라이드마다 핵심은 하나만 말한다.
- 기술 용어를 말한 뒤 다시 쉬운 말로 해석하지 말고 처음부터 쉬운 말을 사용한다.
- A/B/C의 전체 지표를 읽지 말고 가장 차이가 큰 결과 하나만 말한다.
- 확정되지 않은 수치는 만들지 않는다.
- 질문을 받을 만한 세부 내용은 먼저 해명하지 않는다.
- 4분 50초를 목표로 두 번 이상 소리 내어 연습한다.

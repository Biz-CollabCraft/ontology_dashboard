# AI Solution Engineer 5분 발표 압축 대본

- 기준: 본편 8장
- 목표 시간: 4분 40초~5분
- 말하기 원칙: 쉬운 말, 짧은 문장, 한 장당 핵심 하나
- 사용법: `발표 문장`만 실제로 말하고, `질문 유도점`은 슬라이드에 남겨 질의응답으로 넘긴다.
- 수치 원칙: `[실측값]`은 최종 평가 결과로 바꾼다. 결과가 없으면 `평가 중`이라고 말한다.

## 발표에서 남길 메시지 3개

1. 위험 점수만으로는 현장 결정을 내릴 수 없다.
2. 여러 데이터를 같은 시점의 근거로 묶고, AI는 설명만 맡겼다.
3. 좋아진 신뢰성과 늘어난 시간·사용량을 함께 비교했다.

## 1쪽. 예측 점수 → 현장 판단

### 시간

30초

### 발표 문장

안녕하세요. 저는 설비의 고장 위험을 현장의 판단으로 연결하는 부분을 맡았습니다.

현장에서는 위험도만 보고 설비를 멈출 수 없습니다. 생산, 정비, 부품, 품질과 납기를 함께 봐야 합니다. 저는 이 데이터를 같은 판단 시점의 근거로 묶고, 담당자가 이해할 수 있는 문장으로 만드는 서버와 AI 기능을 구현했습니다.

### 질문 유도점

- 왜 예측 모델보다 판단 근거에 집중했는가?
- 개인 구현 범위는 어디까지인가?

### 다음 장 연결

먼저 위험 점수만으로 무엇이 부족한지 보겠습니다.

## 2쪽. 위험도 ≠ 실행 판단

### 시간

25초

### 발표 문장

고장 위험이 0.82이고 상태가 긴급이어도 지금 멈춰야 하는지는 알 수 없습니다. 생산 중인지, 부품과 기술자가 있는지, 품질과 납기에 문제가 없는지 더 확인해야 합니다. 데이터가 없는 것이 아니라, 여러 곳에 흩어져 있다는 점이 문제였습니다.

### 질문 유도점

- 어떤 제조 데이터를 연결했는가?
- 현장 담당자는 기존에 무엇을 따로 확인해야 했는가?

### 다음 장 연결

그래서 데이터를 연결할 때 세 가지 기준을 세웠습니다.

## 3쪽. 설계 기준

### 시간

35초

### 발표 문장

세 가지 기준을 세웠습니다. 첫째, 같은 시점의 데이터만 사용했습니다. 둘째, 조회와 검사는 코드가, 근거 설명은 AI가, 최종 판단은 사람이 맡도록 나눴습니다. 셋째, 새로운 데이터가 늘어나도 전체 구조를 바꾸지 않도록 데이터 종류별 연결 부분을 분리했습니다.

### 질문 유도점

- 같은 시점이라는 것을 어떻게 확인했는가?
- 왜 AI가 작업을 직접 만들지 않게 했는가?
- 새로운 데이터는 어떻게 추가되는가?

### 다음 장 연결

이 기준을 실제 처리 흐름에 적용했습니다.

## 4쪽. 운영 판단 지원 흐름

### 시간

35초

### 발표 문장

먼저 예측 결과와 같은 시점의 근거를 고정하고, 생산·정비·부품·품질·납기 정보를 읽기 전용으로 조회합니다. 코드는 선택지별 근거와 제약을 정리하고, 마지막에 AI가 담당자별 문장으로 바꿉니다. AI는 작업을 만들거나 상태를 바꾸지 않습니다.

### 질문 유도점

- 왜 모든 단계를 AI에 맡기지 않았는가?
- 근거 묶음과 AI 문장을 왜 나눴는가?
- 재시도와 잘못된 응답 검사는 어디에서 하는가?

### 다음 장 연결

데이터 종류가 늘어날 때도 같은 흐름을 유지할 수 있습니다.

## 5쪽. 관계와 확장 구조

### 시간

25초

### 발표 문장

설비는 생산오더, 부품, 기술자, 품질 로트, 납기와 연결됩니다. 각 데이터를 공통된 근거 형식으로 바꿨기 때문에, 새로운 데이터가 추가돼도 해당 데이터를 가져오는 부분만 붙일 수 있습니다. 조회에 실패하면 빈 값을 사실처럼 사용하지 않고 누락 상태로 남깁니다.

### 질문 유도점

- 그래프 데이터베이스를 사용하지 않은 이유는?
- 어느 정도 복잡해지면 지식 그래프가 필요한가?
- 데이터 누락은 화면에 어떻게 보이는가?

### 다음 장 연결

이 근거는 다음과 같이 담당자의 선택지 비교에 사용됩니다.

## 6쪽. 긴급 설비 판단 예시

### 시간

30초

### 발표 문장

이 설비는 위험도가 높고 생산 중이지만 부품이 부족하고 품질 검사가 보류된 상황입니다. 시스템은 답 하나를 추천하지 않습니다. 멈춤, 계획정비, 계속운전마다 가능한 근거와 막힌 이유, 확인할 담당자를 보여주고 최종 선택은 사람이 합니다.

### 질문 유도점

- 추천하지 않으면 AI의 가치가 무엇인가?
- 선택지와 제약은 AI가 만드는가, 코드가 만드는가?
- 사람의 승인 이후에는 어떤 흐름으로 이어지는가?

### 다음 장 연결

## 7쪽. 실패 상황 평가

### 시간

35초

### 발표 문장

막아야 할 실패를 먼저 정하고 테스트했습니다. 오래된 데이터, 작업 생성 요구, 외부 호출 지연과 깨진 AI 응답을 넣어 봤습니다. 같은 시점의 근거만 사용하는지, 실제 작업이 생기지 않는지, 실패한 값을 정상 정보처럼 보여주지 않는지 확인했습니다. 결과는 로컬의 가상 상황 기준입니다.

### 결과가 확정된 경우 덧붙일 문장

`[시나리오 수]개 상황에서 시간 기준은 [실측값], 작업 생성은 [실측값]건, 장애 처리는 [실측값]으로 확인했습니다.`

### 질문 유도점

- 72회 평가를 왜 최소 평가라고 보는가?
- 오래된 데이터는 어떻게 넣고 확인했는가?
- 안전 종료와 대체 응답의 차이는 무엇인가?

### 다음 장 연결

## 8쪽. 신뢰성과 처리 비용 비교

### 시간

45초

### 발표 문장

평가는 세 방식으로 나눴습니다. A는 AI가 바로 답하는 방식, B는 정리된 근거를 주는 방식, C는 응답 검사와 장애 처리까지 적용한 방식입니다.

C는 잘못된 근거와 위험한 응답을 더 잘 막았지만, 응답 시간과 토큰 사용량은 `[실측 변화]`했습니다. 또 잘못된 답을 막는 것뿐 아니라 실제로 사용할 수 있는 답을 얼마나 제공했는지도 확인했습니다.

즉, 정확도 하나가 아니라 신뢰성, 응답 시간, 사용량, 답변 가능 범위를 함께 비교했습니다.

### 질문 유도점

- A/B/C에서 실제 차이가 가장 컸던 지표는?
- 응답 시간이 늘어도 C를 사용할 이유는?
- 안전한 답변 제공률은 어떻게 계산했는가?
- 상황에 따라 B와 C를 나눠 적용할 수 있는가?

# 발표에서 말하지 않고 남겨둘 내용

다음 내용은 본문에서 먼저 설명하지 않는다. 슬라이드에는 짧은 라벨이나 그래프로만 남기고 질문이 나오면 답한다.

| 후킹 포인트 | 본문에서는 | 질문이 나오면 설명할 내용 |
|---|---|---|
| 같은 시점의 근거 | `같은 시점의 데이터만 사용` | 기준시각, 출처, 버전, 저장 전 재확인 |
| AI 책임 범위 | `AI는 설명만 담당` | 읽기 전용 도구, 작업 생성 0건, 사람 승인 |
| 확장성 | `가져오는 부분만 추가` | 데이터별 연결 부분과 공통 근거 형식 |
| A/B/C 비교 | 세 방식의 차이만 설명 | 근거 정리와 검증 단계의 효과 분리 |
| 응답 시간 | 증가 여부만 설명 | p50·p95, 재시도 요청의 긴 지연 |
| 토큰 | 사용량 변화만 설명 | 입력·출력·재시도 토큰 분리 |
| 답변 가능 범위 | `사용할 수 있는 답` | 정상 응답, 제한된 답변, 안전 종료, 위험 응답 |
| 기술 선택 | 본문에서 생략 | LangGraph·지식 그래프를 먼저 넣지 않은 이유 |
| 평가 한계 | `로컬 가상 상황 기준` | 실제 외부 시스템, 장기 운영, 현장 KPI 미검증 |
| 0.75 | 본편에서 생략 | 기존 긴급 경계이며 새 최적값이 아님 |

# 최종 리허설 기준

- 화면의 문장을 전부 읽지 않는다.
- 한 문장을 길게 이어 말하지 않는다.
- 슬라이드마다 핵심은 하나만 말한다.
- 기술 용어를 말한 뒤 다시 쉬운 말로 해석하지 말고 처음부터 쉬운 말을 사용한다.
- A/B/C의 전체 지표를 읽지 말고 가장 차이가 큰 결과 하나만 말한다.
- 확정되지 않은 수치는 만들지 않는다.
- 질문을 받을 만한 세부 내용은 먼저 해명하지 않는다.
- 4분 50초를 목표로 두 번 이상 소리 내어 연습한다.

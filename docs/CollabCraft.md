## **2. 프로젝트 개요**

### **2.1 프로젝트 배경**

제조 현장에서는 설비별로 다양한 센서 데이터가 지속적으로 생성됩니다. 그러나 데이터 형식이 서로 다르고, 이상 징후가 발견되더라도 점검 요청과 정비 결정까지 여러 단계가 분리되어 있습니다.

* 설비별 센서 로그 구조와 표현이 다름
* 대량의 센서 변화를 사람이 직접 비교하기 어려움
* 예측 결과와 현장 점검·정비 업무가 연결되지 않음
* 사용자 역할에 따라 필요한 정보가 다름
* 정비 이후 실제 위험이 감소했는지 확인하기 어려움

### **2.2 프로젝트 목표**

설비 이상 가능성을 조기에 발견하고, 검증된 근거를 바탕으로 사람의 점검과 정비 의사결정까지 연결하는 예지보전 시스템을 구축합니다.

* 센서 로그를 일관된 공통 형식으로 변환
* 설비별 이력을 기반으로 이상 가능성 예측
* 모델별 예측 수치를 운영 위험으로 판정
* 결과와 판단 근거를 함께 제공
* 사용자 역할에 맞는 화면과 업무 기능 제공
* 정비 이후 상태를 다시 예측하여 조치 효과 확인

## **3. 시스템 개요**

### **3.1 사용자 흐름**

#### **생산 관리자**

운영 위험 확인
→ 우선 대응 설비 선택
→ 점검 요청
→ 비용과 조치안 비교
→ 정비안 승인
→ 작업 상태 확인

생산 관리자는 생산 위험과 우선 대응 설비를 확인하고, 현장 점검을 요청합니다. 이후 비용과 조치안을 비교하여 정비 여부를 결정합니다.

#### **현장 엔지니어**

배정된 작업 확인
→ 설비와 센서 상태 확인
→ 판단 근거 검토
→ 점검 결과 기록
→ 정비 수행
→ 작업 결과 등록

현장 엔지니어는 배정된 작업과 설비 상태를 확인하고, 센서 변화와 판단 근거를 바탕으로 점검과 정비를 수행합니다.

#### **경영진**

전체 운영 위험 확인
→ 생산 영향 확인
→ 위험 추세 비교
→ 대응 진행 상황 확인
→ 경영 보고서 검토

경영진은 조직 전체의 설비 위험과 생산 영향을 확인하고, 대응 현황과 주요 결과를 요약된 보고서로 검토합니다.

#### **사용자별 정보 차이**

| 사용자 | 주요 관심 정보 | 주요 행동 |
| ----- | ----- | ----- |
| 생산 관리자 | 생산 위험, 우선순위, 작업 상태, 비용 | 점검 요청, 조치안 검토 및 승인 |
| 현장 엔지니어 | 센서 변화, 설비 상태, 판단 근거, 작업 이력 | 점검, 측정, 정비, 결과 기록 |
| 경영진 | 조직 위험, 생산 영향, 위험 추세, 대응 결과 | 운영 현황과 보고서 확인 |

### **3.2 시스템 아키텍처**

#### **전체 흐름**

설비 센서 데이터 생성
→ 센서 로그 수집
→ 공통 형식 변환
→ 예측 특징 데이터 구성
→ 모델 학습 및 버전 관리
→ 실시간 예측
→ 진단 및 운영 판정
→ 점검·정비 업무 처리
→ 역할별 화면과 보고서 제공
→ 정비 결과 재평가

#### **데이터 생성부**

* 설비별 센서 데이터 생성
* 실제 운영과 유사한 시간 흐름 구성
* 정비 전후 설비 상태 데이터 생성

#### **Generator**

* 새로 추가된 센서 로그 감지
* 지정된 매핑 규칙에 따른 데이터 변환
* 예측 특징 데이터와 정답 데이터 구성
* 복수 모델 학습 및 버전 관리
* 실시간 모델별 이상 가능성 계산
* 모델별 예측 결과와 출처 정보 전송

#### **Backend**

* 모델별 예측 결과 수신 및 검증
* 중복 결과와 잘못된 요청 차단
* 판정 기준값과 운영 정책 적용
* 운영 결과와 판단 근거 생성
* 점검·정비 작업 및 담당자 관리
* 정비 비용 비교와 승인 처리
* 역할별 화면 데이터와 보고서 제공

#### **Frontend**

* 생산 관리자용 운영·작업 관리 화면
* 현장 엔지니어용 설비 상세·현장 작업 화면
* 경영진용 경영 요약·보고 화면
* 역할별 권한에 따른 정보와 기능 제공

#### **LLM 지원 기능**

* 검증된 결과와 근거를 활용한 설명 생성
* 센서 및 정비 이력 기반 검토 지원
* 사용자 역할에 맞는 보고서 작성
* 근거가 확인되지 않은 내용의 사용 제한
* 최종 정비 판단은 사람이 수행

## **4. 세부 설명 및 시연**

### **4.1 세부 설명**

#### **센서 데이터 공통 형식 변환**

센서 로그
→ 지정된 매핑 규칙 적용
→ 공통 형식 센서 데이터셋

* 새로 추가된 로그만 이전 처리 위치부터 순서대로 처리
* 센서 필드, 설비 ID, 시간 표현을 일관된 형식으로 변환
* 일정 시간 구간별 데이터셋 생성
* 파일 내용과 체크섬을 이용한 무결성 확인
* 장애 발생 시 마지막 정상 처리 위치부터 재개

#### **예측 특징 데이터 구성과 모델 학습**

설비 관측 데이터 + 고장 이력
→ 예측 특징 데이터
→ 복수 모델 학습
→ 모델 실행 파일 묶음 발행

* 설비별 데이터를 시간순으로 정렬
* 서로 다른 설비의 관측 이력이 섞이지 않도록 분리
* 이전 값, 변화량, 이동 통계 등 예측에 필요한 값 생성
* 실제 고장 이전 일정 시간대를 예측 대상으로 지정
* LightGBM, XGBoost, Random Forest 모델 학습
* 모델, 입력 구조, 예측 기준과 성능 결과를 버전별로 보존

#### **실시간 예측 결과 생성 및 전송**

새로운 설비 데이터
→ 예측용 데이터 생성
→ 활성 모델별 예측
→ 모델별 예측 결과 묶음 전송

* 예측에 필요한 과거 관측 이력 확인
* 입력 항목과 학습 조건의 일치 여부 검증
* 사용할 모델 파일과 버전 확인
* 모델별 이상 가능성 수치 계산
* 설비, 관측 시간, 모델 버전과 예측 수치를 함께 전송
* 오류 유형에 따라 즉시 중단하거나 제한적으로 재시도

#### **예측 결과 수신 및 운영 판정**

모델별 예측 결과
→ 요청과 출처 검증
→ 판정 기준 적용
→ 운영 결과와 판단 근거 생성

* 데이터 형식과 필수 항목 검증
* 반복 수신된 결과의 중복 반영 방지
* 모델별 예측 수치에 판정 기준값 적용
* 설비의 위험 수준과 이상 여부 결정
* 모델과 데이터의 출처 및 처리 이력 보존
* 검증된 결과만 화면, 보고서, 알림과 정비 업무에 제공

#### **역할별 화면 제공**

* 생산 관리자: 생산 위험, 우선순위, 점검 요청, 비용 검토, 정비안 승인
* 현장 엔지니어: 센서 변화, 판단 근거, 배정 작업, 점검 및 정비 결과
* 경영진: 조직 위험, 생산 영향, 위험 추세, 대응 상태, 경영 보고서
* 시스템 운영자: 매핑 규칙, 운영 파일, 모델, 재처리 작업, 감사 기록과 로그

#### **근거 기반 AI 검토 지원**

운영 결과 + 판단 근거 + 센서·정비 이력 + 작업 지침
→ AI 검토
→ 설명과 보고서

* 시스템에서 검증된 자료만 입력으로 사용
* 설명에 사용된 센서 및 정비 이력 연결
* 제공된 자료와 맞지 않는 내용 제한
* AI 기능을 사용할 수 없을 때 기본 요약 제공
* AI는 설명을 지원하며 최종 판단은 담당자가 수행

#### **점검·정비와 결과 재평가**

점검 요청
→ 현장 점검
→ 비용과 조치안 비교
→ 정비 승인
→ 정비 수행
→ 정비 후 상태 재예측

* 생산 관리자가 위험 설비의 점검 요청 생성
* 현장 엔지니어가 요청을 수락하고 점검 수행
* 측정값과 점검 결과 기록
* 적용 가능한 정비 방안과 비용 비교
* 생산 관리자가 정비안 승인
* 현장 엔지니어가 정비 결과 기록
* 정비 효과가 반영된 설비 상태를 다시 예측
* 조치 전후의 위험 변화를 비교
